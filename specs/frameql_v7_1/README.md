# ToD v7.1 / Frame-QL — reviewed working successor set (STAGED, NOT PUBLISHED)

**Staged:** 7 September 2026 · **Status:** working successor documents under review
**This directory is not a publication, not a release, and not a description of shipped behaviour.**

## What this is, in one paragraph

The joint consistency review of *The Theory of Data* v7.1 (Full Manuscript Working Draft 0.4) and its
Frame-QL companion set completed on 7 September 2026 and found no new cross-document contradiction
requiring a theory revision. This directory stages that reviewed set for repository review, with the
two supplied editorial corrections (J1, J2) applied in `proposed_adoption/`. **No merge, publication,
deployment, reindexing, or implementation is authorized by this staging**, and nothing here changes
parser grammar, planner or engine behaviour, operator or family admission, capability IDs or schema,
profile promises, measured build coverage, type definitions, wire fields, contract version, or serving
outcomes.

## Why this set lives in `specs/` and not in `docs/`

`docs/README.md` states the repository's publication rule directly: *"The merge that published these
files is the publication."* Placing an unpublished working successor under `docs/` would therefore
**be** an act of publication, which this mission explicitly excludes. `specs/` is the established home
for working specifications and already carries subdirectories, so this placement introduces no new
document architecture — it uses the one the repository has.

The distinction the review asks to preserve maps onto structure that already exists:

| jurisdiction | where it lives | what it claims |
|---|---|---|
| published theory and historical editions | Zenodo deposits + `registry/publications/` | published, DOI-bearing |
| shipped-language documentation | `docs/frame_ql_language.md` and the three companion documents | what the **released** build means and runs |
| authored profile obligations | `docs/core_profile.md`, `docs/platform_profile.md`, `specs/profiles/` | what a conforming implementation must support |
| measured build coverage | `docs/frame_ql_build_status.md` | generated by measurement, never authored |
| **working successor theory and language** | **this directory** | **reviewed, unpublished, not conformance evidence** |

A title containing "Manual", "canonical" or "law" on a file in this directory does not make it the
shipped authority. Nothing here is evidence that the current build implements it.

## Layout, and what each part is for

```
specs/frameql_v7_1/
   START_HERE.md                     the review package's own entry point
   README.md                         this file — repository staging status and reading index
   reviewed_sources/                 the reviewed set, PRISTINE — byte-identical to the review package
   proposed_adoption/                the two J1/J2-corrected files, and only those
   historical_provenance/            historical evidence — NOT active instructions
   audit_joint_review.py             re-runnable file-integrity audit
   MANIFEST_SHA256.json              covers every packaged file except itself
   J1_editorial_correction.diff      the supplied unified diffs, retained as adoption evidence
   J2_editorial_correction.diff
   tod_frameql_joint_*.{md,json}     review report, forty-case ledger, corrections, manifests, audit
```

`reviewed_sources/` is deliberately **not** edited. The review package preserves its baselines rather
than overwriting their provenance, and the supplied diffs are written against a
`reviewed_sources/ -> proposed_adoption/` pair, so that convention is reproduced here rather than
invented. The consequence worth knowing: to read a corrected document you read `proposed_adoption/`;
to verify what was reviewed you read `reviewed_sources/`.

## Superseded working guidance — do not execute it

`historical_provenance/` and the superseded documents named in the index are **evidence at their
snapshots, not instructions.** In particular, the withdrawn categorical FIRST/LAST-family exclusion,
the universal formation-locality veto, and the older compulsory-migration recommendations are **not**
current design authority and must not be reactivated by citation. Earlier CC mission texts (M2, O1,
O2 reconnaissance) are historical mission records; they authorize nothing.

Superseding a recommendation does not rewrite an observed historical implementation fact. Where those
reports recorded reproduced behaviour, the behaviour remains reported.
