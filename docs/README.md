# docs/ — the Columna manuals

The authoritative home of the Columna manuals. **The merge that published these files is the
publication** (ADR-034 D5 + ADR-035 D4; residency ruling 2026-07-14); nothing manual-shaped travels by
upload after that.

## The manuals
- [`columna_reference_manual_5e.md`](columna_reference_manual_5e.md) — the reference manual (5th ed.):
  the object model, the definition language (Chapter 26), the Certificate layer (Part VI).
- [`columna_framework_manual_6g.md`](columna_framework_manual_6g.md) — the framework manual (6th ed.,
  revision 6g; terminology aligned with Theory of Data v4.0 — measure/member/series, 2026-08-03).
  [`columna_framework_manual_6f.md`](columna_framework_manual_6f.md) (v3.1) and
  [`columna_framework_manual_6e.md`](columna_framework_manual_6e.md) are retained as prior-edition
  records. **They are not current and they contain retired product claims** — each opens with a
  standing banner saying so. Read them as evidence of what was once claimed.
- **The Frame-QL documents (four, by jurisdiction).** One book was split on 2026-09-01 because a
  single document cannot state what the language means, what an implementation must support, and what
  today's build runs without those three drifting apart in the same sentence.
  - [`frame_ql_language.md`](frame_ql_language.md) — **what Frame-QL means.** Canonical language law,
    independent of any build. No version stamps, no roadmap marks.
  - [`core_profile.md`](core_profile.md) — **what a conforming Core implementation must support.**
    A contract, authored.
  - [`platform_profile.md`](platform_profile.md) — **what Platform adds over Core.** Currently
    nothing, which is a statement rather than an omission.
  - [`frame_ql_build_status.md`](frame_ql_build_status.md) — **what the shipped build actually runs.**
    Generated by measurement; never authored.

  Capability tables in all four are projections of one authority
  (`specs/frameql_capabilities.toml` and `specs/profiles/`), regenerated and drift-checked in CI, so
  the same disposition can no longer be claimed differently in two places.

- [`frame_ql_language.md`](frame_ql_language.md) — the Frame-QL query-language manual (Second Edition;
  supersedes the First Edition). **Its own Currency block is the authority on which release it is
  current for** — this index deliberately does not restate the version, because a number repeated in
  two places goes stale in one of them, and this one had (it read `0.14.0` / wire `"2"` while the
  manual said `0.18.0` / contract `"4"`).

Each construct in the reference manual's Chapter 26 carries a shipping status mark
(**[SHIPPED vX.Y]** · **[SCHEDULED — <WP>]** · **[ROADMAP — <note>]**); unmarked constructs do not
exist (ADR-034; the honest-hatching idiom). The Frame-QL manual documents the **shipped envelope
grammar** as canonical (`columns @ anchor`); its historical Coframe-QL canonical form is retained as a
lineage appendix (ADR-035).

## tools/ — the regeneration harness (the manual's integrity rule)
Every executable Frame-QL example is a ```frameql query block followed by a ```frameql-output block
that is **machine-generated by running the query against the shipped package** — the site's build-time
integrity rule, extended to the manual. See [`tools/regen_examples.py`](tools/regen_examples.py):

    python docs/tools/regen_examples.py            # rewrite every frameql-output block
    python docs/tools/regen_examples.py --check     # CI: fail on any run error or output drift

"The manual is structurally incapable of documenting a query it did not run." CI runs `--check`
(`.github/workflows/docs.yml`); an example that stops parsing, errors, or whose answer drifts fails the
build. `tools/SAMPLE_regeneration.md` is the harness's own smoke fixture.

## Working successors are NOT here — and that is the point

The reviewed ToD v7.1 / Frame-QL working successor set is staged at
[`specs/frameql_v7_1/`](../specs/frameql_v7_1/README.md), deliberately outside `docs/`, because of the
rule at the top of this file: **the merge that publishes a file into `docs/` is the publication.** An
unpublished working successor placed here would be published by the act of landing it.

So the four Frame-QL documents above continue to describe **the shipped release** and nothing else.
The successor set describes a *proposed* analytical interpretation that this build does not implement,
carries no DOI, and is not conformance evidence. Neither one is a version of the other:

- **`docs/frame_ql_language.md`** — what the released language means. Read it to know what the build does.
- **`specs/frameql_v7_1/`** — the reviewed v7.1 successor target. Read it to know what is proposed.

Superseded working rulings inside that set (the withdrawn categorical FIRST/LAST-family exclusion, the
universal formation-locality veto, older migration recommendations) are retained as historical evidence
and are **not** current design authority. Do not implement from them.
